## この接続・公開作業の主な追加・修正ファイル

- `.gitattributes`：Windows/macOS間の改行形式を明示。
- `config/update.json`：専用リポジトリの更新先を設定。
- `pubspec.yaml`：公開版バージョンを更新。
- `scripts/release_automation.py`：下書きの取得・作成応答ID利用・公開前検証を修正。
- `scripts/recover_release.py`：元の3ビルドを検証し、成果物だけを再利用して公開する処理を追加。
- `.github/workflows/recover-release.yml`：公開復旧用Actionsを追加。
- `scripts/test_release_automation.py`、`scripts/test_release_recovery.py`：回帰テストを追加。
- `ai_worker/test_worker.py`：配布版指定時に同梱FFmpegもテストするよう修正。
- `README.md`、`docs/自動リリースと更新通知.md`、本書：接続先、運用手順、確認結果。

自動ビルドは既存の `.github/workflows/release.yml`、`scripts/build_windows.ps1`、`scripts/build_macos.sh` を使用します。更新通知本体は `lib/services/update_service.dart` と `lib/screens/update_button.dart` です。

## 残る注意点・ユーザー操作

- 更新機能のない旧1.1.2は、最初の1回だけ1.2.4以降を手動インストールしてください。
- v1.2.4以降はGitHub APIが回数制限中でも、Releaseの`latest.json`へ自動フォールバックします。
- 更新機能は自動検出と通知・ダウンロード案内です。インストールやアプリ置換は利用者が行います。
- Mac版はアドホック署名で、Developer ID署名とApple公証は未設定です。他のMacでは初回の起動確認が必要になる場合があります。Windowsの商用コード署名も追加していません。
- 失敗した1.2.0/1.2.1等の下書きは公開されていないため、利用者の更新通知には出ません。
- Windowsで今後開発する際は、この専用リポジトリをcloneしてください。旧フォルダに未反映の変更があればバックアップして差分を取り込み、別履歴の強制pushは避けてください。
