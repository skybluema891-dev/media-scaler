# 自動リリースと更新通知

この機能を追加したバージョンは `1.2.0+5` です。以前の1.1.2には更新チェックがないため、最初の1回は更新機能付きの版を手動インストールしてください。

## 初回接続

専用の公開リポジトリは https://github.com/skybluema891-dev/media-scaler です。Mac作業フォルダのoriginとして接続し、mainブランチをpush済みです。Windows側ではこのリポジトリをcloneして作業してください。既存Windows作業フォルダに未反映の変更がある場合は、バックアップしてから新しいcloneへ差分を取り込みます。別履歴の強制pushは行わないでください。

```powershell
git clone https://github.com/skybluema891-dev/media-scaler.git
cd media-scaler
```

`config/update.json` の `repository` に `OWNER/REPOSITORY` を設定します。GitHub Actionsで作るアプリには `github.repository` がビルド時に自動埋め込みされます。通常のローカルビルドはconfigの値を使用し、`UPDATE_REPOSITORY` 環境変数で上書き可能です。

認証不要で利用者が更新チェック・ダウンロードできるよう、対象リポジトリのReleaseが公開されている必要があります。非公開ソースを維持する場合は公開用の別リポジトリと転送設定が追加で必要です。アクセストークンをアプリへ埋め込まないでください。

## Windows側での普段の更新

1. `pubspec.yaml` の `version` を上げます。例：`1.2.4+9` → `1.2.5+10`。
2. 修正をコミットし、GitHubの既定ブランチ（通常main）へpushします。PRの場合は既定ブランチへマージします。
3. ActionsでWindows、Apple Silicon Mac、Intel Macをビルドします。
4. 全ビルドとテストに成功すると `v1.2.5` タグを作り、配布ファイル5点、SHA256SUMS.txt、API制限時用latest.jsonをアップロードしてReleaseを公開します。
5. 更新機能付きの旧版アプリは、次の起動時に新バージョンを通知します。右上の「更新を確認」ボタンでも確認できます。

既定ブランチ以外のpushは解析・テストのみです。バージョンの`+`より後だけを変更しても新Releaseにはしません。公開済みの版を作り直さず、パッチ番号以上を上げてください。

タグによる公開も可能です。ソースのversionと完全一致するタグを作ってpushしてください。

```powershell
git tag v1.2.5
git push origin v1.2.5
```

GitHub Actionsの「Run workflow」を既定ブランチで実行すると、現在のversionが未公開の場合に再ビルド・公開します。失敗した実行はRe-run jobsでも再試行可能です。

同一版の公開済みReleaseは上書きしません。失敗時に残る下書きは再試行で補完します。既存タグが別コミットを指す場合は停止します。全OS分が揃うまで下書きのため、利用者に未完成の更新を通知しません。

### ビルド成功後、公開処理だけが失敗した場合

Actionsの `Recover release publication` → `Run workflow` で、元の `Build desktop releases` の実行IDを入力できます。Windows・Mac ARM64・Mac Intelの全ビルドが成功した実行だけを受け付け、元のコミットとタグを維持して成果物を再利用します。成果物が期限切れの場合は再ビルドが必要です。

CLIでは修正済みmainを取得後、`retry-release-実行ID-再試行番号` というタグを作ってpushしても起動できます。通常の新バージョン公開にはこの復旧タグは不要です。Macのpushはログイン済みGitHub Desktop経由で確認済みです。CLIの認証は別途必要です。

## アプリ側の動作

- 起動時にGitHubの最新の公開済み安定版ReleaseをHTTPSで確認します。
- バージョンは数値で比較します。1.10.0は1.9.0より新しく、同じ版・古い版・プレリリースは通知しません。
- Windowsはsetup.exe、Apple Siliconはarm64.dmg、Intel Macはx86_64.dmgを案内します。
- 通知からダウンロードまたは変更内容を標準ブラウザーで開きます。アプリの置換・インストーラー実行は利用者が行います。
- 「あとで」は次回起動時に再通知。「この版をスキップ」はその版のみ自動通知を抑えます。手動確認では再表示します。
- GitHub APIが403/429の回数制限中は、Releaseの`latest.json`へ自動フォールバックします。
- ネットワーク切断・タイムアウトは起動や変換を妨げません。手動確認時には理由を表示します。
- ユーザー画像・動画、保存先パス、認証情報は更新チェックで送信しません。

## CIと署名

既存のFFmpeg、AIワーカー、WindowsインストーラーとMacパッケージ生成スクリプトを使います。GitHubの標準GITHUB_TOKENを公開ジョブだけcontents:writeにし、追加PATなしで同じリポジトリへ公開します。

macOSは引き続きアドホック署名です。Developer ID署名・Apple公証は別途証明書と認証情報の設定が必要です。他のMacで初回警告が出る可能性があります。Windowsも既存の署名状態を維持しています。

参考：GitHub Release API https://docs.github.com/en/rest/releases/releases
