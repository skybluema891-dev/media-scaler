## 1080p・2K・4Kの動画性能

Windows 2で同梱のFFmpegとAIワーカーを計測した。合成素材は動きのある映像とAAC音声。通常変換は24 fpsで4秒（96フレーム）、AIは2 fpsで1秒（2フレーム）。入力と出力は1080p（1920×1080→1280×720）、2K（2560×1440→1920×1080）、4K（3840×2160→2560×1440）。通常変換は同じバイキュービック縮小で、CPUはCRF 23、Quick Syncはglobal quality 23。AIは「高速」設定を使用した。比較画像の指標はバイキュービック縮小とのSSIMで、AIによる見た目の改善を判定する用途には使っていない。

時間にはプロセスの起動と終了が含まれる。メモリはWindowsでサンプリングしたプロセスツリー全体のワーキングセットのピークで、GPU専用メモリは含まない。GPU使用率は該当プロセスが使った個別のGPUエンジンのピーク。短い処理でサンプルが取れなかった箇所は未計測とした。計測は短い合成素材を各条件1回ずつ使った。

各欄は実時間（秒）とピークメモリ（MiB）。

| 処理 | 1080p | 2K | 4K |
| --- | ---: | ---: | ---: |
| デコード＋縮小のみ | 1.65 / 未計測 | 1.04 / 未計測 | 2.19 / 未計測 |
| H.264 CPU | 2.60 / 未計測 | 3.59 / 494.2 | 5.54 / 931.9 |
| H.264 Quick Sync | 4.21 / 89.6 | 3.96 / 91.3 | 7.88 / 497.3 |
| H.265 CPU | 6.77 / 379.0 | 7.82 / 622.8 | 20.84 / 1,029.9 |
| H.265 Quick Sync | 5.67 / 260.1 | 5.24 / 362.5 | 9.17 / 572.6 |
| AI Vulkan | 40.51 / 239.0 | 69.61 / 291.8 | 145.40 / 508.0 |
| AI CPU | 148.47 / 198.9 | 180秒で打ち切り / 231.8 | 180秒で打ち切り / 355.2 |

- すべての通常変換で映像96フレームと音声を確認し、FFmpegで映像をデコードした。SSIMは0.9932〜0.9976。4K H.265はQuick SyncがCPUの約2.3倍速く、ワーキングセットも小さかった。4K H.264ではCPUが速かった。Quick SyncのメモリはGPU専用メモリを含まないため、CPU側との合計メモリ比較には使えない。
- デコード＋縮小だけの処理は1.0〜2.2秒。4KのH.265で完了までに時間を要した主な差は、エンコードと関連する音声処理・ファイル書き出しが加わった段階にある。
- Vulkanの3Dエンジンのピークは1080p・2K・4Kで35%、35%、42%。Quick SyncのH.265で取得できたピークは3Dが22〜31%、VideoDecodeが6〜12%。短いサンプリングでVideoEncodeのピークは取得できなかった。
- AIの成功出力は指定寸法のH.264、音声付き2フレームで、SSIMは0.9933〜0.9953。Vulkan実行ファイル内の時間はGPUの総時間40.51／69.61／145.40秒に対し29.40／65.26／137.23秒だった。4Kではバッチ前後が約6.4秒、バッチ処理内でVulkan実行以外が約1.8秒だった。Vulkan実行ファイル内の推論と転送は個別に計測していない。CPUの1080pは148.47秒のうち145.34秒がAIバッチ処理にかかった。
